## Предварительно

Тебе понадобится:

- **Windows 10/11**
- **NVIDIA GPU** с актуальным драйвером. Проверь, что драйвер стоит:
  ```powershell
  nvidia-smi
  ```
  Команда должна показать таблицу с видеокартой и версией CUDA. Если её нет — поставь [драйвер NVIDIA](https://www.nvidia.com/Download/index.aspx). Отдельно ставить CUDA Toolkit **не нужно**: нужные CUDA/cuDNN приезжают pip-колёсами вместе с зависимостями.
- **Микрофон**
- Клавиша F19/F20/F21 на клавиатуре или способ их сгенерировать. На обычных клавиатурах F13–F24 нет — их шлют макро-клавишами или через AutoHotkey. Если такой возможности нет, назначь в `.env` привычные комбинации (`ctrl+alt+...`) — см. [настройку](#настройка-env).

## Python 3.12

Скачай Python 3.12 с [python.org](https://www.python.org/downloads/) и установи. При установке **поставь галку «Add Python to PATH»**.

Проверь:
```powershell
py -3.12 --version
```
Должно вывести `Python 3.12.x`.

> Почему именно 3.12: на нём собраны и проверены версии зависимостей из `requirements.txt`. На 3.13 некоторые колёса (ctranslate2, numpy) могут ещё не иметь бинарников.

## Установка проекта

```powershell
git clone https://github.com/<你>/aqualocal.git
cd aqualocal

py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Установка тянет ~2 ГБ (CUDA/cuDNN колёса). На медленном канале это надолго — это нормально, повторно они возьмутся из pip-кэша.

> **Важно про venv:** всегда вызывай интерпретатор полным путём `.venv\Scripts\python.exe`, а не через активацию. Если перенесёшь папку проекта на другой диск, `.exe`-обёртки (`pip.exe` и пр.) сломаются — но `python.exe -m pip` продолжит работать. Починить обёртки: `.venv\Scripts\python.exe tools\fix_venv_paths.py --apply --backup`.

Создай рабочие копии конфигов из шаблонов:
```powershell
copy .env.example .env
copy singularity\aliases.json.example singularity\aliases.json
```

## Проверка CUDA

Прежде чем ставить токены — убедись, что GPU виден:
```powershell
.venv\Scripts\python.exe test_cuda.py
```

Ожидаемый вывод содержит `✅ CUDA доступна` и список типов вычислений с `float16`. Если видишь `❌ CUDA не обнаружена` — переходи в [диагностику](#диагностика), дальше двигаться нет смысла.

## Токен SingularityApp

Нужен только для режима F20 (задачи). Если Singularity не используешь — пропусти этот раздел, F19 и F21 работают без него.

1. Нужна подписка с доступом к REST API (тариф **Elite**).
2. Открой личный кабинет: **https://me.singularity-app.com/rest-tokens**
3. Создай токен. Дай ему права на запись для сущностей: **Проект, Задача, Заметка, Тег**.
4. Скопируй токен — он показывается один раз. Существующий токен отредактировать нельзя, только пересоздать.
5. Вставь его в `.env` в поле `SNG_TOKEN` (см. ниже).

> Токен — это доступ на запись в твой аккаунт. Не коммить `.env`, не пересылай токен в переписке. `.env` уже в `.gitignore`.

Проверить, что токен рабочий и подтянуть список проектов/тегов:
```powershell
.venv\Scripts\python.exe -m singularity.sender --list
```
Команда выведет твои проекты (`P-...`) и теги (`A-...`). Эти ID пригодятся для `aliases.json` и `SNG_DEFAULT_PROJECT`.

## HuggingFace

**Токен HuggingFace не нужен.** Это частый вопрос, поэтому явно:

Модель `large-v3` качается с публичного репозитория [Systran/faster-whisper-large-v3](https://huggingface.co/Systran/faster-whisper-large-v3) анонимно, при первом запуске `app.py`. Детектор речи (VAD) идёт локально в составе пакета. Ничего авторизовать не надо.

Токен HuggingFace потребовался бы только если добавлять gated-модели — например, диаризацию (разделение по говорящим) через pyannote в WhisperX. В AquaLocal этого нет.

Куда качается модель: кэш HuggingFace, обычно `%USERPROFILE%\.cache\huggingface\hub`. Первый запуск скачивает ~1.5 ГБ, дальше берётся из кэша. Если нужно положить кэш в другое место — задай переменную окружения `HF_HOME`.

## Настройка `.env`

Открой `.env` в редакторе. Формат: `КЛЮЧ=значение`, без кавычек, обратные слэши в путях писать как есть (не экранировать).

Минимум, что нужно проверить/заполнить:

```ini
# --- SingularityApp (F20) ---
SNG_TOKEN=<вставь сюда токен из ЛК>
SNG_DEFAULT_PROJECT=            # P-... для проекта по умолчанию, пусто = Входящие

# --- Obsidian (F21) ---
OBS_INBOX_DIR=E:\vaults\my\Входящие    # существующая папка для файлов дня

# --- Горячие клавиши ---
HOTKEY_INSERT=f19
HOTKEY_TASK=f20
HOTKEY_NOTE=f21
```

**Горячие клавиши.** Если F19–F21 недоступны, поставь комбинации:
```ini
HOTKEY_INSERT=ctrl+alt+i
HOTKEY_TASK=ctrl+alt+t
HOTKEY_NOTE=ctrl+alt+n
```
Синтаксис — как у пакета `keyboard`: имена клавиш через `+`, модификаторы `ctrl`/`alt`/`shift`/`win`. Осторожно с системными сочетаниями (`ctrl+c`, `alt+tab`, `win+d`) — приложение перехватит их глобально. Полный разбор — в комментариях `.env.example`.

**Алиасы** (`singularity/aliases.json`) — заполни, если Whisper стабильно калечит какое-то имя проекта/тега (латиница, аббревиатуры). Формат — в шаблоне. Не обязательно на старте.

## Первый запуск

```powershell
.venv\Scripts\python.exe app.py
```

Что происходит:
1. В консоль/лог пишется загрузка модели (первый раз — со скачиванием, ~1.5 ГБ).
2. Через ~30 сек — сигнал готовности (звук) и иконка в трее.
3. Наведись на иконку — увидишь назначенные хоткеи.

Проверь по очереди: зажми клавишу вставки, скажи фразу, отпусти — текст должен появиться в активном поле. То же для задачи и заметки.

Логи пишутся в `aqualocal.log` в папке проекта. При первом запуске запускай именно `python.exe` (а не `pythonw.exe`/`start.bat`) — консоль покажет нативные ошибки CUDA, которые логгер не всегда ловит.

Когда всё работает — для повседневного использования запускай тихо, без консоли:
```powershell
start.bat
```
или двойным кликом по `start_aqualocal.vbs` (вообще без мелькающего окна).

## Автозапуск

Чтобы AquaLocal стартовал при входе в Windows:

1. Нажми `Win+R`, введи `shell:startup`, Enter — откроется папка автозагрузки.
2. Создай там ярлык на `start_aqualocal.vbs` (правый клик по файлу → «Создать ярлык», перенеси ярлык в папку автозагрузки).

`.vbs` берёт путь относительно себя, поэтому проект можно перемещать — ярлык чинить не придётся, если сам `.vbs` остаётся в папке проекта.

Убрать из автозапуска — удали ярлык из `shell:startup`.

## Обновление

```powershell
cd aqualocal
git pull
.venv\Scripts\python.exe -m pip install -r requirements.txt   # если менялись зависимости
```

Твои `.env`, `aliases.json`, кэш и очереди не трогаются — они в `.gitignore`. После обновления сверься с `.env.example`: если там появились новые параметры, перенеси их в свой `.env`.

## Диагностика

**`❌ CUDA не обнаружена` в test_cuda.py**
- Проверь драйвер: `nvidia-smi`. Нет вывода → переустанови драйвер NVIDIA.
- Убедись, что ставил зависимости в тот же venv, которым запускаешь.
- CUDA/cuDNN приезжают колёсами `nvidia-cublas-cu12`, `nvidia-cudnn-cu12` — проверь, что они установились: `.venv\Scripts\python.exe -m pip list | findstr nvidia`.

**Модель «висит» на загрузке, нет строки `Модель успешно загружена`**
- Обычно VRAM занята другим процессом. Проверь `nvidia-smi` — если там LM Studio, игра или другой ML-процесс держат память, `large-v3` в FP16 (~3 ГБ) может встать намертво вместо честной ошибки. Освободи VRAM.
- Сними зависшую копию: `taskkill /F /IM pythonw.exe`, затем запусти через `python.exe` (не `pythonw`), чтобы увидеть нативную ошибку.

**Хоткеи не срабатывают**
- Пакету `keyboard` для глобального перехвата нужны права. Запусти терминал/ярлык от имени администратора.
- Проверь, что заданная в `.env` клавиша реально доходит до системы (например, F19 без макро-клавиатуры не нажать). Попробуй временно `HOTKEY_*=ctrl+alt+...`.

**Задача со сроком падает в очередь (`HTTP 400 ... ISO-8601`)**
- Это чинилось: даты теперь отправляются с временем и таймзоной. Если видишь такую ошибку в старой `singularity/queue.jsonl` — она осталась с прошлых версий. Дошли накопленное: `.venv\Scripts\python.exe -m singularity.sender --flush`.

**Задача уходит «во Входящие», хотя называл проект**
- Whisper мог исказить имя. Глянь `aqualocal.log` — там пишется, что не распозналось и с каким score. Понизь `SNG_FUZZY_THRESHOLD` в `.env` или добавь алиас в `singularity/aliases.json`.

**venv сломался после переноса на другой диск (`pip.exe` не запускается)**
- `.venv\Scripts\python.exe tools\fix_venv_paths.py` — покажет, что не так.
- `.venv\Scripts\python.exe tools\fix_venv_paths.py --apply --backup` — починит обёртки.
- Правило на будущее: в перенесённом venv вызывай `python.exe -m <модуль>` вместо `<модуль>.exe`.

**Ничего не помогает**
- Смотри `aqualocal.log` — там стадии запуска и трейсбеки. Приложи его к issue.
