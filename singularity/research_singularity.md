# Подключение SingularityApp к Claude через API и MCP: полное руководство

## TL;DR
- **У SingularityApp есть официальный REST API и официальный MCP-сервер** (оба на тарифах Pro и Elite, запущены в конце 2025 года) — писать свой MCP «с нуля» не нужно: рекомендуемый путь — подключить готовый официальный MCP через .mcpb-бандл из личного кабинета либо (для Claude Code) обратиться напрямую к REST API на `https://api.singularity-app.com`.
- **Аутентификация — статический Bearer-токен** с гранулярными правами по сущностям, создаётся в личном кабинете (`me.singularity-app.com/rest-tokens`); OAuth нет, вебхуков/стримов событий нет, повторяющиеся задачи через API не создаются.
- **API покрывает почти весь функционал** (задачи, проекты, секции, канбан, чек-листы, привычки, теги, тайм-трекинг — полный CRUD), поэтому при желании легко написать тонкую обёртку-MCP для Claude Code, но для большинства сценариев достаточно официального решения.

## Key Findings

1. **Официальный API существует и хорошо задокументирован.** REST API `v2` на базовом хосте `https://api.singularity-app.com`, интерактивная документация — Swagger по адресу `https://api.singularity-app.com/v2/api` (доступ после создания токена). Русская вики: `singularity-app.ru/wiki/api/`, английская: `singularity-app.com/wiki/api/`.
2. **Официальный MCP-сервер тоже существует** — первый-party, удалённый, на том же хосте `https://api.singularity-app.com`. Подключается через .mcpb-бандл, скачиваемый из личного кабинета (`me.singularity-app.com/mcp`). Документация: `singularity-app.com/wiki/mcp/`.
3. **Запуск состоялся в конце 2025 года.** В блоге «Итоги 2025» (singularity-app.ru/blog/itogi-2025/) разработчики прямо объявили: «Открыли доступ к API — управляйте задачами, проектами и привычками через свои скрипты. Добавили поддержку MCP для подключения к SingularityApp Claude Desktop и других нейросетей». Это же подтверждает РБК Компании в материале об итогах года.
4. **И API, и MCP требуют платного тарифа** (Pro или Elite) и используют один и тот же Bearer-токен.
5. **Community/сторонних MCP-серверов для SingularityApp нет** — в каталогах (glama.ai, mcp.so, smithery, pulsemcp) записи отсутствуют; на GitHub/npm/PyPI пакетов нет. Официальное решение — единственное.
6. **Ограничения API:** нет вебхуков, потоков событий и подписок на изменения; нельзя создавать повторяющиеся (рекурсивные) задачи; общие (shared) проекты не возвращаются в выдаче.

## Details

### 1. Официальный REST API SingularityApp

**Наличие и документация.** SingularityApp предоставляет полноценный публичный REST API (версия `/v2`). Полная интерактивная документация — Swagger по адресу `https://api.singularity-app.com/v2/api`; она автогенерируется и доступна после получения токена. Текстовые описания методов — в вики: `https://singularity-app.ru/wiki/api/` (рус.) и `https://singularity-app.com/wiki/api/` (англ.). GraphQL нет — только REST. Вебхуков нет: цитата из вики — «The API currently does not support webhooks, event streams, or subscriptions to changes».

**Аутентификация.** Используется статический токен доступа (Bearer). Порядок:
1. Зайти в личный кабинет `https://me.singularity-app.com`, раздел «API Access» / «Доступ к API» (прямая ссылка `me.singularity-app.com/rest-tokens`).
2. Нажать «Создать токен», задать имя и выбрать сущности (задачи, проекты, привычки, теги и т. д.), с которыми токен сможет работать (гранулярные права create/edit/delete).
3. Скопировать токен и передавать в каждом запросе в заголовке `Authorization: Bearer <token>`.

Токен привязан к одному аккаунту, редактированию не подлежит (только удаление и пересоздание). OAuth не поддерживается.

**Тариф.** API и MCP доступны только на тарифах Pro и Elite. Цитата из FAQ: «Yes! The public API is available in the Pro and Elite plans». Актуальные цены (по состоянию на 22.07.2026 по данным каталогов mediarost.com и softadvisor.ru): Pro — от 209 ₽/мес при годовой оплате (249 ₽/мес помесячно), Elite — 250 ₽/мес при годовой (299 ₽/мес помесячно), пробный период 14 дней без привязки карты. Бесплатный Basic API не даёт.

**Возможности API (полный CRUD).** Четыре операции: Create (POST), Read (GET), Update (PATCH), Delete (DELETE). Основные эндпоинты:
- **Задачи** — `/v2/task`. Поля: `title` (обяз.), `start` (ISO), `note`, `priority` (0 — высокий, 1 — обычный, 2 — низкий), `isNote`, `journalDate` (в архив), `deleteDate` (в корзину). Фильтры GET: `includeRemoved`, `includeArchived`, `maxCount`, `offset`, `projectId`, `parent`, `startDateFrom`/`startDateTo`, `includeAllRecurrenceInstances`.
- **Канбан-статус задачи** — `/v2/kanban-task-status` (POST, перенос задачи между колонками: `taskId`, `statusId`).
- **Чек-листы** — `/v2/checklist-item` (GET/POST/PATCH/DELETE; `title` + `parent` = ID задачи).
- **Проекты** — `/v2/project`. Поля: `title` (обяз.), `note`, `isNotebook`, `emoji` (hex, напр. `1f49e`), `color` (HEX). Общие проекты в выдачу не попадают.
- **Колонки канбана** — `/v2/kanban-status`; **секции** — `/v2/task-group` (`title` + `parent` = ID проекта).
- **Привычки** — `/v2/habit` (+ `/v2/habit-progress` для отметок: `habit`, `date` YYYY-MM-DD, `progress` 0/1/2).
- **Теги** — `/v2/tag` (`title`, `parent`, `hotkey` как Unicode-код).
- **Тайм-трекинг** — `/v2/time-stat` (`start`, `secondsPassed`, `taskId`, `type` TIME/BREAK) + `/v2/time-stat/delete-bulk`.

**Лимиты и ограничения.** Пагинация через `maxCount` + `offset`. Нет вебхуков/стримов/подписок. Нельзя создавать повторяющиеся задачи (только через интерфейс приложения). Официальные числовые rate-limits в публичной документации не указаны.

**Известные интеграции.** Штатные способы ввода задач: Telegram-бот `@SingularityAppBot` (Pro/Elite), добавление по email (Pro/Elite, со спецсимволами: `!` — дедлайн, `@` — тег), голосовой ввод, виджеты, Яндекс Алиса. Двусторонняя синхронизация с Google Calendar, веб-календари iCal, локальный iOS-календарь. Универсальные интеграторы (Albato, ApiX-Drive, Zapier) готовых коннекторов к SingularityApp, судя по публичным данным, не имеют — но теперь их можно построить поверх REST API через HTTP-модуль «универсального коннектора». Отдельно отметим: в приложении есть встроенный **AI-ассистент** (бета) в двух режимах — Ask (ответы о продуктивности) и Agent (создание/редактирование/удаление задач), доступный на Pro/Elite; для запросов к моделям SingularityApp расходуются внутренние SPC-баллы, а на Elite можно подключить свои модели/провайдеров (в т. ч. локальные через Ollama) без списания SPC.

### 2. MCP для SingularityApp

**Официальный MCP-сервер есть.** Это первый-party решение, а не community-проект. Архитектурно — удалённый сервер на `https://api.singularity-app.com`, к которому Claude Desktop подключается через .mcpb-бандл, скачиваемый из личного кабинета (`me.singularity-app.com/mcp`). Документация: `https://singularity-app.com/wiki/mcp/` (рус. зеркало — `singularity-app.ru/wiki/mcp/`).

**Как устроено подключение (по официальной вики):**
1. Создать токен в разделе «API Access» (те же права по сущностям, что и для API).
2. Скачать конфигурационный файл (.mcpb) из раздела «MCP Configuration» личного кабинета.
3. В Claude Desktop установить этот файл штатным способом; в окне подключения вставить токен и указать адрес сервера `https://api.singularity-app.com`.
4. Для не-Claude-нейросетей: переименовать `.mcpb` → `.zip`, распаковать и подключить по инструкции соответствующего клиента.
5. Скопировать «базовый промпт» из раздела MCP-конфигурации в настройки нейросети (в Claude Desktop — Settings → Profile → Personal Preferences) и указать свой часовой пояс.

.mcpb — это стандартный MCP Bundle (формат Anthropic, ранее назывался DXT, переименован в MCPB в сентябре 2025; ZIP-архив с `manifest.json`). Токен — тот же Bearer, что и для API; OAuth нет.

**Транспорт — важная неясность.** Официальная вики даёт только базовый адрес `https://api.singularity-app.com`, но НЕ указывает точный транспорт (streamable-HTTP vs SSE) и путь MCP-эндпоинта (напр. `/mcp`). Формулировки «укажите адрес сервера» + «вставьте токен в окно подключения» указывают на удалённый HTTP-эндпоинт, но публично не подтверждено, оборачивает ли .mcpb локальный stdio-прокси. Это стоит проверить эмпирически (см. Recommendations).

**Список MCP-инструментов не опубликован.** Вики говорит: документация автогенерируется, «Claude сам разберётся, какие методы API SingularityApp использовать». Инструменты повторяют REST-эндпоинты (задачи, проекты, секции, канбан, чек-листы, привычки, теги, тайм-стат). Точные имена tools публично не приведены.

**Community MCP-серверов нет.** В каталогах glama.ai, mcp.so, smithery.ai, pulsemcp записей SingularityApp нет; на GitHub/npm/PyPI пакетов нет. (Результаты вроде «Super Singularity MCP» и «Singular MCP» относятся к другим продуктам — курс-платформе и маркетинг-аналитике Singular.net соответственно, к SingularityApp отношения не имеют.)

**Можно ли написать свой MCP поверх API.** Да, и это тривиально: API покрывает полный CRUD по всем ключевым сущностям, аутентификация простая (один Bearer-заголовок). Единственные пробелы — отсутствие вебхуков (значит, только polling для «реактивных» сценариев) и невозможность создавать повторяющиеся задачи. Для Claude Code разумнее либо использовать официальный сервер, либо тонкую обёртку.

### 3. Практика подключения

**Claude Desktop (рекомендуемый штатный путь):** установить скачанный .mcpb через Settings → Extensions (Desktop Extensions), в окне подключения ввести Bearer-токен и адрес `https://api.singularity-app.com`, вставить базовый промпт в Personal Preferences, указать таймзону. При первом вызове каждого метода Claude запросит разрешение — выбрать «Allow Always».

**Claude Code (официально не задокументировано).** SingularityApp прямо снимает с себя поддержку подключения к конкретным ИИ-сервисам («SingularityApp support is unable to advise on connecting MCP to any AI services»). Официальных инструкций, команды `claude mcp add` или упоминания `mcp-remote` для SingularityApp нет. Возможные (непроверенные) пути:
- Если сервер отдаёт HTTP-транспорт: `claude mcp add --transport http singularity https://api.singularity-app.com/<path> --header "Authorization: Bearer <token>"` — путь нужно уточнить эмпирически.
- Через мост `mcp-remote`: распаковать .mcpb (→ .zip), изучить `manifest.json`, вытащить фактический эндпоинт и обернуть через `npx mcp-remote <url> --header "Authorization: Bearer <token>"`.
- Самый простой прагматичный путь для senior-разработчика: не использовать MCP вовсе, а дать Claude Code ссылку на Swagger `https://api.singularity-app.com/v2/api` и токен, и работать с REST API напрямую (в т. ч. из 1С через HTTP-запросы). Есть публичное свидетельство работоспособности такого подхода: на эфире один из спикеров подключил SingularityApp к Claude Code, «просто скинув ссылку на страницу с документацией — Claude сам нашёл документацию, разобрался с API и всё настроил».

**Пример конфигурации (шаблон для случая HTTP-транспорта, требует проверки пути):**
```json
{
  "mcpServers": {
    "singularityapp": {
      "type": "http",
      "url": "https://api.singularity-app.com/<mcp-path>",
      "headers": { "Authorization": "Bearer <ВАШ_ТОКЕН>" }
    }
  }
}
```

**Пример прямых запросов к API (curl):**
```bash
# Создать задачу
curl -X POST https://api.singularity-app.com/v2/task \
  -H "Authorization: Bearer $SNG_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"Купить продукты","start":"2026-07-24","priority":0,"note":"молоко, хлеб"}'

# Получить задачи проекта с пагинацией
curl "https://api.singularity-app.com/v2/task?projectId=P-123&maxCount=10&offset=0" \
  -H "Authorization: Bearer $SNG_TOKEN"

# Обновить задачу (PATCH, title необязателен)
curl -X PATCH https://api.singularity-app.com/v2/task/T-456 \
  -H "Authorization: Bearer $SNG_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"priority":1}'
```
(ID задачи начинается с «T», проекта — с «P»; ID можно взять из ответа при создании либо через ПКМ → «копировать приватную ссылку».)

**Подводные камни.**
- Точный MCP-транспорт/путь публично не задокументирован — потребуется разбор .mcpb.
- Поддержка со стороны SingularityApp ограничена рамками Swagger; кастомные интеграции они не настраивают.
- Нет вебхуков → реактивные сценарии только через polling.
- Нельзя создавать повторяющиеся задачи через API/MCP.
- Общие проекты не возвращаются API.
- Требуется постоянный платный тариф; при его окончании токены перестают работать.
- Реверс-инжиниринг закрытого внутреннего API приложения не требуется — публичный API официален и достаточен.

### 4. Альтернативы и сравнение с конкурентами

**Обходные пути (если MCP не заведётся или не нужен):**
- **Email-в-задачу** (Pro/Elite): отправка письма на персональный адрес; в теме `!` задаёт дедлайн (`!24.05.2025`, `!завтра`, `!следующий вторник`), `@` — тег. Легко автоматизируется из 1С/скриптов через отправку почты.
- **Telegram-бот** `@SingularityAppBot`: приём текста/файлов, распознавание дат/проектов/тегов, список на сегодня/завтра, прямые ссылки на задачи. Одна из самых популярных функций.
- **Календарные фиды**: двусторонняя синхронизация с Google Calendar, iCal-веб-календари, локальный iOS-календарь.
- **Импорт/экспорт**: импорт из Todoist, TickTick, Things, MS To Do, OmniFocus, Notion, Evernote, CSV; экспорт шаблонов проектов.
- **Прямая работа с REST API** из любого языка/1С — самый гибкий путь.

**Сравнение с конкурентами (как образец подхода):**
- **Todoist** — эталон: официальный MCP от Doist (`Doist/todoist-mcp`, ранее пакет `@doist/todoist-ai`), remote HTTP-эндпоинт `https://ai.todoist.net/mcp` с OAuth. Для Claude Code самый быстрый путь — две команды: `/plugin marketplace add doist/todoist-mcp` затем `/plugin install todoist@doist`, ручной вариант — `claude mcp add --transport http todoist https://ai.todoist.net/mcp` с браузерной OAuth-авторизацией. Обёртки над официальным пакетом дают ~35 инструментов. SingularityApp в этом уступает: нет OAuth, нет официальной поддержки Claude Code, транспорт не задокументирован.
- **TickTick** — официального MCP нет, зато богатая экосистема community-серверов (`jacepark12/ticktick-mcp`, `karbassi/mcp-ticktick`, `alexarevalo9/ticktick-mcp-server` и др.) поверх Open API (OAuth). Для SingularityApp такой экосистемы пока нет — но собственный официальный API это компенсирует.

Что стоит «взять за образец» у Todoist для будущей своей MCP-обёртки: небольшой набор высокоуровневых инструментов под целостные сценарии (а не голый CRUD 1:1), поддержка OAuth и remote HTTP-транспорта, публикация в каталогах MCP.

## Recommendations

**Рекомендуемый путь по приоритету:**

1. **Первый выбор — официальный MCP через Claude Desktop.** Оформите Pro/Elite, создайте токен с нужными правами (`me.singularity-app.com/rest-tokens`), скачайте .mcpb (`me.singularity-app.com/mcp`), установите в Claude Desktop, вставьте базовый промпт и таймзону. Это самый быстрый и поддерживаемый путь. **Порог переключения:** если .mcpb не устанавливается в вашу версию Claude Desktop или транспорт несовместим — переходите к п. 2.

2. **Для Claude Code — прямая работа с REST API либо тонкая обёртка-MCP.** Как senior-архитектор интеграций, дайте Claude Code Swagger-ссылку (`https://api.singularity-app.com/v2/api`) и токен, и работайте с REST напрямую (этот подход публично подтверждён как рабочий); либо распакуйте .mcpb (→ .zip), извлеките эндпоинт/транспорт из `manifest.json` и подключите через `mcp-remote` или `claude mcp add --transport http`. Для повторяемости напишите ~150 строк MCP-обёртки на TypeScript/Python поверх CRUD-эндпоинтов (по образцу todoist-ai: высокоуровневые tools «создать задачу», «список на сегодня», «переместить в канбане»). **Порог:** если нужны реактивные сценарии (триггеры на изменения) — API их не даёт, используйте polling или обходные пути.

3. **Обходные пути** (email-to-task, Telegram-бот) — для быстрой односторонней подачи задач без ИИ, в т. ч. из 1С, когда MCP избыточен.

**Проверочные шаги перед продакшеном:**
- Эмпирически определите транспорт и путь MCP-эндпоинта (распаковав .mcpb или через MCP Inspector: `npx @modelcontextprotocol/inspector`).
- Протестируйте лимиты запросов на своём аккаунте (публичных чисел нет).
- Для командных сценариев учтите, что shared-проекты API не возвращает.

## Caveats
- **Транспорт и точный путь официального MCP-эндпоинта публично не задокументированы** — в отчёте указан только базовый адрес `https://api.singularity-app.com`. Конфиг для Claude Code в разделе Details — шаблон, требующий эмпирической проверки.
- **Список имён MCP-инструментов не опубликован** — они автогенерируются и повторяют REST-эндпоинты.
- **Официальной поддержки подключения к Claude Code / Claude Desktop со стороны SingularityApp нет** — компания явно снимает с себя эту поддержку.
- **Цены и состав тарифов** приведены по состоянию на 2026 год и могут меняться; проверяйте на `singularity-app.ru/price/`.
- **Числовые rate-limits API** в публичных источниках не найдены.
- Часть деталей (например, что MCP и API используют один токен) взята из личного кабинета/вики; Swagger доступен только после авторизации, поэтому полная схема полей проверяется уже с токеном на руках.
