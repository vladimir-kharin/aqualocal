## Суть

Плашка оверлея (индикатор записи, статус распознавания, подтверждения) **скрывается другими окнами**.
Нужно, чтобы она была видна поверх всего — иначе теряется единственная обратная связь приложения:
звуков в программе нет намеренно.

## Что известно

`RecordingOverlay.__init__` выставляет `root.attributes('-topmost', True)` **один раз при создании**
(`app.py:533`). Этого недостаточно:

- окно с `overrideredirect(True)` не участвует в обычном z-порядке менеджера окон Windows;
- другие приложения, объявившие себя topmost (плееры, конференции, игры в безрамочном полноэкранном
  режиме), встают выше — Windows выбирает последнего, кто заявил topmost;
- стиль `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_TRANSPARENT` (`app.py:559-572`) делает окно
  неактивируемым и click-through, поэтому «поднять фокусом» его нельзя в принципе — только средствами WinAPI;
- показ/скрытие сделано через `-alpha`, а не `withdraw()` (намеренно — чтобы не дёргать фокус),
  значит окно физически существует всё время и его позиция в z-порядке устаревает.

## Направления решения (выбрать при реализации)

1. **Периодически переутверждать topmost.** В `_tick`, когда плашка видима, вызывать
   `SetWindowPos(hwnd, HWND_TOPMOST, 0,0,0,0, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)`.
   Дёшево, не трогает фокус (`SWP_NOACTIVATE` обязателен). Раз в несколько кадров, не каждый —
   30 вызовов в секунду избыточны.
2. **Переутверждать только в момент показа** (переход `shown = False → True`) — минимальное
   вмешательство; поможет, если окно теряет позицию редко.
3. **Пересоздавать topmost-флаг через tkinter** (`attributes('-topmost', False)` → `True`) — работает,
   но иногда вызывает мигание.
4. Крайний случай — стиль `WS_EX_LAYERED` + отдельное окно уровня «banner»; сложнее и вряд ли нужно.

Начать стоит с (1) + (2): переутверждать при показе и раз в ~0.5 с, пока плашка видна.

## Что сделано (2026-08-14)

Реализованы направления (1) + (2), правки только в `app.py`:

- перед классом `RecordingOverlay` заданы **явные прототипы WinAPI** (`_user32.GetParent`,
  `GetWindowLongW`, `SetWindowLongW`, `SetWindowPos`). До этого `ctypes` считал аргументы
  32-битными и на 64-битной Windows мог обрезать хендл окна — скрытая мина, из-за которой
  click-through мог не примениться;
- `_make_clickthrough` сохраняет хендл в `self.hwnd`;
- новый `_reassert_topmost()` — `SetWindowPos(hwnd, HWND_TOPMOST, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)`;
- новый `_show()` заменил три одинаковых блока показа в `_tick`: поднимает плашку при показе
  и переутверждает раз в `TOPMOST_EVERY = 15` кадров (~0.5 с), пока она видна.

Проверено скриптом на отдельном окне (`F:\tmp\test_topmost.py`): хендл получен корректно, все
четыре стиля (`NOACTIVATE`, `TOOLWINDOW`, `TRANSPARENT`, `TOPMOST`) выставлены, `SetWindowPos`
вернул `True`, окно переднего плана после вызова не изменилось.

### Границы: чего этот подход не покроет

- **эксклюзивный полноэкранный DirectX** — оверлей не отображается вообще; borderless-полноэкранный
  (браузер по F11, конференции, современные игры) перекрывается нормально;
- **окна с привилегией UIAccess** (экранная лупа, экранная клавиатура) сидят в более высокой
  z-полосе; обойти можно только манифестом `uiAccess=true` с подписью и установкой в `Program Files` —
  делать не планируем;
- **защищённый рабочий стол UAC** — отдельный десктоп, чужого там не видно;
- если чужое приложение тоже переутверждает topmost по таймеру — слои будут перемигиваться.

## Критерии приёмки

- плашка видна поверх полноэкранного браузера, поверх окна конференции и поверх окна RDP (`mstsc`);
- фокус ввода при этом никуда не уходит: диктовка в чужое окно и вставка по F19 работают как раньше;
- клики сквозь плашку продолжают проходить в окно под ней;
- плашка не появляется в Alt+Tab и на панели задач;
- нет мигания при показе и скрытии.
