## Суть

Вести историю распознанных фрагментов: **сохранять аудио и распознанный текст**, чтобы к ним можно
было вернуться — перечитать, переслушать и **вставить текст повторно**.

Сегодня после распознавания фраза живёт ровно один раз: уходит в курсор (F19), в трекер (F20) или в
файл дня (F21). Если вставка попала не в то окно, текст перезаписан или Whisper ошибся — восстановить
нечего: аудио выбрасывается, текст остаётся только строкой в `aqualocal.log`.

## Что уже есть в коде

- готовый массив `float32` 16 кГц сразу перед распознаванием — `audio_np` в `process_audio`
  (`app.py:441`); для серверного пути — `audio` после `decode_audio` (`app.py:350`);
- текст, режим и длительность в том же месте (`app.py:454-464`);
- отработанный шаблон дискового хранилища: `queue.jsonl` (JSON Lines с `ts`, `text`, служебными
  полями) — см. `docs/kb/Оффлайн_очереди_и_сохранность_фраз.md`;
- механизм подтверждающих плашек `flash()` — годится для отклика «скопировано в буфер»;
- меню в трее (`app.py:707-713`) — очевидное место для пункта «История».

## Вопросы, которые надо решить до реализации

1. **Формат аудио.** WAV 16 кГц моно — это ~1.9 МБ на минуту (32 КБ/с), без зависимостей.
   OGG/Opus — на порядок меньше, но нужен кодировщик (PyAV уже есть в зависимостях faster-whisper).
   Предложение: WAV на старте, сжатие — если объём станет проблемой.
2. **Срок и объём хранения.** Ротация по количеству (последние N фрагментов) и/или по возрасту
   (N дней) и/или по суммарному размеру. Нужна цифра от владельца; разумный старт — 200 последних
   фрагментов и 14 дней, что бы ни наступило раньше.
3. **Где хранить.** `history/` в корне проекта (рядом с очередями) — просто, но это личные данные:
   папку обязательно в `.gitignore`, репозиторий публичный (см.
   `docs/kb/Форк_upstream_и_приватность.md`). Альтернатива — папка вне репозитория, путь в `.env`
   (`HISTORY_DIR`).
4. **Индекс.** `history/index.jsonl`: `{"ts", "mode", "seconds", "text", "audio": "2026-08-13_204231.wav",
   "target": "куда ушло"}`. Тем же форматом легко потом отдавать историю наружу.
5. **Как смотреть и вставлять повторно.** Варианты по возрастанию сложности:
   - пункт трея «Последние 10» → выбор → текст в буфер обмена (и/или сразу `Ctrl+V`);
   - отдельное окно истории на tkinter: список, текст, кнопки «Копировать», «Вставить», «Слушать»,
     «Перераспознать»;
   - только файлы + внешний просмотр (минимум работы, но не решает «вставить повторно» одним движением).
   Предложение: начать с пункта трея; окно — вторым шагом, если понадобится.
6. **Записывать ли фрагменты локального STT-сервера** или только свои горячие клавиши. Чужие запросы
   могут быть объёмными; предложение — по умолчанию нет, включаемо флагом.
7. **Перераспознавание.** Раз аудио сохранено, можно прогнать его другой моделью или с другими
   параметрами. Ценная возможность, но это отдельный шаг после базовой истории.

## Принятые решения (2026-08-14, владелец)

| Вопрос | Решение |
|---|---|
| Когда сохранять аудио | **до распознавания**, сразу после сборки массива — фраза остаётся, даже если Whisper упал или VAD её съел |
| Формат | WAV 16 кГц моно (`wave` из stdlib, без зависимостей) |
| Сколько хранить | 10 последних, старые удаляются вместе с аудио |
| Где | `history/` в корне репозитория, папка в `.gitignore` |
| Просмотр | окно на tkinter (не пункт трея) |
| Действия | копировать текст, распознать заново, прослушать (плеер по умолчанию) |
| Фрагменты STT-сервера | не пишем |

Отступление от исходного плана: индекс — `index.json` (список), а не `index.jsonl`. Записей всего
десять, а результат распознавания дописывается к уже существующей записи — переписать маленький
список целиком проще, чем чинить append-only формат очередей.

## Что сделано (2026-08-14)

Новые файлы:

- **`history_store.py`** — хранилище: `save()` (до распознавания), `update()` (дописать текст
  и статус), `recent()`, `read_audio()`, ротация до `HISTORY_KEEP`. Свой `load_env()`, как у
  остальных модулей; операции с индексом под замком — его трогают рабочий поток, поток
  STT-сервера и окно истории. CLI: `.venv\Scripts\python.exe -m history_store`.
- **`history_window.py`** — окно (`Toplevel`): список записей, полный текст, кнопки «Копировать
  текст», «Распознать заново», «Прослушать». Одно окно на приложение. Повторное распознавание
  уходит в отдельный поток, результат забирается из очереди по таймеру окна — иначе mainloop
  встал бы на секунды вместе с оверлеем. Список сам подхватывает новые диктовки (раз в 0.7 с),
  перестраивается только при изменениях, чтобы не сбрасывать выделение.

Врезки в `app.py`:

- импорт модулей истории в `try` — без них приложение работает как раньше;
- `ui_queue` — команды из трея главному потоку; разбираются в `_handle_ui_commands()` внутри
  `_tick` оверлея (виджеты tkinter можно трогать только в потоке mainloop);
- `recognize_fn` — ссылка на распознаватель, ставится в `stt_worker` после загрузки модели;
- в `process_audio`: `save()` до VAD, затем `update()` со статусом `нет речи` / `распознано` /
  `ошибка`;
- пункт трея «История…».

Статусы записи: `записано` → `распознано` | `нет речи` | `ошибка`.

Параметры `.env`: `HISTORY_ENABLED`, `HISTORY_DIR`, `HISTORY_KEEP` (описаны в `.env.example`).
`history/` добавлена в `.gitignore` — записи голоса не должны уехать в публичный форк.

### Чем проверено

- `history_store` на синтетическом аудио: 5 записей при `KEEP=3` → в индексе 3, лишние WAV
  удалены, `read_audio()` возвращает исходный float32;
- окно с фиктивным распознавателем: список строится, копирование работает, повторное
  распознавание обновляет индекс, второе открытие поднимает то же окно;
- риск с `Toplevel` снят заранее: окно не наследует `overrideredirect` / `WS_EX_NOACTIVATE`
  главного окна-оверлея и нормально принимает фокус;
- **живьём с моделью не проверено** — на момент правки работала старая копия приложения.

## Черновой план

1. Параметры в `.env`: `HISTORY_ENABLED`, `HISTORY_DIR`, `HISTORY_KEEP_COUNT`, `HISTORY_KEEP_DAYS`,
   `HISTORY_SERVER` — с дефолтами в коде (см. `docs/kb/Конфигурация_через_env.md`).
2. Модуль `history/store.py`: `save(audio_np, sample_rate, text, mode, target)`, `recent(n)`,
   `prune()`; запись WAV через `wave` из stdlib, индекс — JSON Lines. Пакет независим от
   `singularity`/`obsidian`, как и они друг от друга.
3. Врезка в `process_audio` **после** успешного распознавания и **до** доставки, в `try` — сбой
   истории не должен ломать основной сценарий.
4. Пункт трея «История» с последними записями → копирование в буфер.
5. Прунинг при старте и после каждой записи.
6. `history/` в `.gitignore`.

## Критерии приёмки

- после диктовки в `history/` появляются WAV и строка индекса; текст совпадает с ушедшим по назначению;
- из трея видны последние фразы, выбор кладёт текст в буфер обмена;
- ротация работает: старые фрагменты удаляются вместе со строками индекса;
- при выключенной истории (`HISTORY_ENABLED=0`) поведение и производительность не меняются;
- сбой записи истории не мешает вставке, отправке задачи и записи заметки.
