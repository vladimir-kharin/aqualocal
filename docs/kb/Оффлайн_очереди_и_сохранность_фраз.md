# Оффлайн-очереди: продиктованное не теряется

Сквозной принцип проекта: **любая произнесённая фраза где-то остаётся**, даже если всё внешнее лежит.

## Лестница отступления

Режим «задача» (F20) устроен так (`app.py:263-283`):

1. **сначала** дубль строкой в дневник Obsidian с тегом `задача` — до всякой сети;
2. потом отправка в SingularityApp;
3. отправка не удалась → фраза в `singularity/queue.jsonl`, плашка «в очередь: …»;
4. и Obsidian недоступен → `obsidian/queue.jsonl` (через `enqueue` модуля);
5. и сам модуль `obsidian.writer` не импортировался → `enqueue_note_fallback` в `app.py:286` пишет
   тот же jsonl своими силами, без модуля.

**Почему дубль пишется до отправки, а не после:** запись в локальный файл почти не может не удаться,
а сеть может. Если сначала ходить в API, то при его недоступности задача осталась бы только в
машинной очереди — глазами её не видно, и человек про неё забудет. Строка в дневнике видна сразу.
Сбой дубля намеренно не мешает отправке в API — он весь в `try` и только логируется (`app.py:240-260`).

**Как применять:** новый приёмник добавлять по той же схеме — локальная фиксация, потом внешний
вызов, потом очередь; каждая ступень ловит исключение предыдущей и не роняет остальные.

## Формат очередей

Обе очереди — JSON Lines, по записи на строку:

```json
{"ts": "2026-08-13T20:31:39", "text": "…", "sent": false, "reason": "почему не ушло"}
```

`extra_tags` добавляется в очереди Obsidian для дубля задачи. Файлы `singularity/queue.jsonl` и
`obsidian/queue.jsonl` — в `.gitignore`.

## Разбор очередей

Происходит **сам, при следующей успешной операции**: `send_task` в конце вызывает `flush_queue`
(`sender.py:69-73`), `append_note` — свой (`writer.py:229-233`). Отдельного фонового потока нет:
пока не диктуешь, очередь не разгребается. Вручную:

```powershell
.venv\Scripts\python.exe -m singularity.sender --flush
.venv\Scripts\python.exe -m obsidian.writer --flush
```

Тонкости, которые легко сломать:

- **первая же неудача обрывает разбор** (`break`) — внешний сервис всё ещё лежит, остальные записи
  не трогаем и не плодим ошибок;
- **отправленные записи вычёркиваются, файл переписывается целиком**; когда всё ушло — удаляется;
- **время берётся из записи, а не текущее** (`writer.py:282`) — заметка попадёт в файл того дня,
  когда была продиктована, а не когда разгрузилась очередь;
- **защита от рекурсии**: `append_note` в конце разбирает очередь, а очередь разбирается тем же
  `append_note`. Без флага `_flushing` (`writer.py:38`) первая же запись в очереди уводит в
  бесконечный цикл. При правке этих функций флаг не убирать.
