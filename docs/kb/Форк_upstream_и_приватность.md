# Форк, upstream и приватность

## Расклад репозиториев

| Remote | Адрес | Роль |
|---|---|---|
| `origin` | `https://github.com/vladimir-kharin/aqualocal` | наш форк, сюда пушим |
| `upstream` | `https://github.com/neo-flashman/aqualocal` | оригинал (Дмитрий Волов), push отключён (`DISABLED`) |

Ветка одна — `master`. На 2026-08-13 форк совпадает с апстримом: последний общий коммит
`0eb00b7 feat: визуальная обратная связь вместо звуков и локальный сервер распознавания`.
Лицензия — MIT.

**Почему это важно для доработок:** проект дорабатывается под личные сценарии владельца, но остаётся
форком живого публичного проекта. Значит:

- изменения, которые полезны всем (исправления, диагностика, конфигурируемость), стоит делать
  так, чтобы их можно было предложить в upstream отдельным коммитом;
- личные умолчания (пути к vault, конкретные хоткеи, интеграции с соседними проектами владельца)
  выносятся в `.env`, а не зашиваются в код — иначе форк невозможно синхронизировать;
- перед крупной доработкой полезно посмотреть, не сделано ли это уже наверху:
  `git fetch upstream && git log --oneline master..upstream/master`.

**Как применять:** новую работу вести коммитами на `master` форка; при конфликте с upstream
переносить чужие изменения (`git merge upstream/master`), а не переписывать историю.

## Что не должно попасть в публичный репозиторий

`.gitignore` уже закрывает: `.env`, `singularity/cache.json` (названия и ID личных проектов),
`singularity/aliases.json`, обе `queue.jsonl` (тексты продиктованного), `aqualocal.log`,
`singularity/openapi*.json`, `.venv/`, `.obsidian/`.

Это же ограничение действует на **базу знаний и задачи**: `docs/kb/` и `docs/tasks/` трекаются в git
и уедут в публичный форк. В карточках и описаниях задач не должно быть токенов, имён личных проектов
из трекера, содержимого дневника и путей к личным хранилищам. Пути вида `E:\vaults\...` допустимы
только как пример из `.env.example`, который и так публичен.

Отдельно: аудио и распознанный текст никуда не отправляются — распознавание локальное; в облако
уходит только текст задачи и только по F20. Любая доработка, которая начинает слать данные наружу
(облачные модели, телеметрия, синхронизация), меняет обещание проекта из `README.md` — такое
согласуется с владельцем и отражается в README.
