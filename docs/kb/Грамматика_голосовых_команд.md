# Грамматика голосовых команд

Разбор — не NLP-модель, а **маркерная грамматика**: ведущие слова-маркеры съедаются с начала фразы
в любом порядке, остаток становится заголовком задачи (`singularity/parser.py:222`).
Каноничное описание с примерами — в docstring того же файла и в `USAGE.md`.

| Маркер | Синонимы | Результат |
|---|---|---|
| `проект <имя>` | в проект, проекте, проекту | `projectId` (fuzzy по кэшу) |
| `тег <имя>` | тэг, с тегом, тегами | `tags[]`, можно несколько раз |
| `срок <дата>` | дедлайн, до, крайний | `deadline` (конец дня 23:59) |
| `на <дата>` | дата, начало, начать | `start` (начало дня 9:00) |
| `важно` | срочно, важное, приоритет | `priority = 0` |
| `неважно` | потом, низкий | `priority = 2` |
| `описание <текст>` | заметка, подробности, детали, комментарий | `note`, забирает весь хвост |

Даты: `сегодня`, `завтра`, `послезавтра`, день недели, `через N дней/недель/месяцев`, «15 августа»,
«15 августа 2026», `24.12`, `24.12.2026`. **Прошедшая дата без года переносится на следующий год**
(`parser.py:144`, `parser.py:159`).

## Три приёма, на которых держится качество

**Маркер `описание` ищется во всей фразе, остальные — только в голове** (`parser.py:228-232`).
Речь идёт естественно: «проект дом купить окна описание позвонить замерщику» — описание всегда в
конце, а проект и срок всегда в начале.

**Span имени не пересекает другой маркер** — `_take_entity` (`parser.py:190`) жадно пробует 1–4 слова
подряд, но останавливается на любом слове из `STOP`. Иначе в «проект дом срок 15 августа» именем
проекта стало бы «дом срок 15».

**Имя не распозналось — грамматика не рвётся.** Если дальше по фразе идёт другой маркер, всё до него
считается кривым именем и съедается; иначе съедается ровно одно слово, чтобы не утащить в никуда
весь заголовок (`parser.py:216-218`).

## Сопоставление имён (fuzzy + алиасы)

Whisper слышит «а семь», а проект называется «А7» — поэтому имена не сравниваются буквально
(`singularity/client.py:68-127`):

- нормализация: нижний регистр, `ё → е`, выброс пунктуации;
- метрика: `max(fuzz.ratio, 0.85 × fuzz.token_set_ratio)` из `rapidfuzz`. Голый `token_set_ratio` дал
  бы 100 для «тег срочно доделать акт» против тега «срочно» — поэтому основа `ratio`, штрафующая
  лишние слова, а `token_set` идёт с понижающим весом как страховка от перестановки;
- порог `SNG_FUZZY_THRESHOLD` (по умолчанию 75). Ниже порога проект/тег не проставляется;
- `singularity/aliases.json` — ручные соответствия «как я это произношу» → ID. Нужны там, где fuzzy
  бессилен: латиница против кириллицы («митинг ассистент» никогда не сматчится с «Meeting Assistant»)
  и произнесённые по буквам аббревиатуры («один эс» → тег «1С»). Файл личный, в `.gitignore`;
- `rapidfuzz` не установлен — молчаливый откат на `difflib` из stdlib, качество ниже (`client.py:77`).

**Ничего не теряется.** Всё, что не распозналось, копится в `warnings` и дописывается в описание
задачи строкой `[aqualocal] ...` (`parser.py:320-322`), а в лог идёт причина и набранный score.
Задача ушла «во Входящие» вместо проекта — смотреть `aqualocal.log`, затем либо понижать порог,
либо добавлять алиас.

## Проверка без микрофона

```powershell
.venv\Scripts\python.exe -m singularity.parser "проект дом срок завтра заказать окна"   # только грамматика
.venv\Scripts\python.exe -m singularity.sender --dry "проект ВЛП купить хлеб"           # + резолв имён, без отправки
.venv\Scripts\python.exe -m obsidian.writer --dry "тег 1с посмотреть вебинар"           # разбор заметки
```

Те же маркеры тегов переиспользует запись в Obsidian — импортом из этого модуля,
см. [[Запись_в_Obsidian_файл_дня]].
