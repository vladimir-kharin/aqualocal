# Конфигурация через `.env`

Единственный источник настроек — файл `.env` в корне. Публичный шаблон с комментариями к каждому
параметру — `.env.example`; сам `.env` в `.gitignore`.

Формат: `КЛЮЧ=значение`, без кавычек, обратные слэши в путях **не** экранируются, пробелы по краям
обрезаются, строки с `#` — комментарии. Табуляцию в значении не набрать руками, поэтому в
`OBS_LINE_FMT` пишется `\t` и разворачивается в модуле (`obsidian/writer.py:63-65`).

## Решение: свой мини-парсер, продублированный в каждом модуле

Функция `load_env()` написана трижды — в `app.py:118`, `singularity/client.py:41`,
`obsidian/writer.py:42`. Это не недосмотр.

**Почему:** зависимости `python-dotenv` нет намеренно (лишний пакет ради 10 строк), а пакеты
`singularity` и `obsidian` должны оставаться **независимыми друг от друга и от `app.py`**: запись
заметок обязана работать даже при развалившейся интеграции с API, и каждый модуль запускается
как самостоятельный CLI (`python -m obsidian.writer ...`).

**Как применять:** новый параметр добавляется в `.env.example` с комментарием и читается тем модулем,
который им пользуется. Не заводить общий модуль настроек, пока не появится третий потребитель одного
и того же значения; тогда — отдельный модуль без импортов из соседей.

## Где какие дефолты

Значения по умолчанию зашиты в коде, а не только в `.env.example`, — приложение должно стартовать
с пустым `.env`:

| Параметр | Дефолт | Где |
|---|---|---|
| `HOTKEY_INSERT/TASK/NOTE` | `f19` / `f20` / `f21` | `app.py:136` |
| `OBS_TASK_TAG` | `задача` | `app.py:153` |
| `STT_PORT` | пусто → сервер не поднимается | `app.py:328-333` |
| `SNG_BASE_URL` | `https://api.singularity-app.com` | `singularity/client.py:55` |
| `SNG_TIMEOUT` / `SNG_CACHE_TTL` | `10` / `600` секунд | `singularity/client.py:57-58` |
| `SNG_FUZZY_THRESHOLD` | `75` | `singularity/client.py:59` |
| `SNG_NOTE_FORMAT` | `plain` (не менять, см. [[Интеграция_SingularityApp_API]]) | `singularity/client.py:61` |
| `OBS_INBOX_DIR` | `E:\vaults\personnel\personnel\Входящие` + предупреждение в лог | `obsidian/writer.py:61,75` |
| `OBS_DATE_FMT` / `OBS_TIME_FMT` | `%Y-%m-%d` / `%H:%M` | `obsidian/writer.py:69-70` |
| `OBS_LINE_FMT` / `OBS_HEADING` | `- {time}\t{text}` / `# {date}` | `obsidian/writer.py:71-72` |
| `OBS_RESOLVE_TAGS` | `1` (сверять теги с кэшем НСИ) | `obsidian/writer.py:73` |

**Модель, язык и частота дискретизации в `.env` не вынесены** — это константы `app.py:155-157`
(`SAMPLE_RATE=16000`, `MODEL_SIZE="large-v3"`, `LANGUAGE="ru"`), как и `device="cuda"`,
`compute_type="float16"` в вызове `WhisperModel` (`app.py:405`). Смена модели или переход на CPU
сегодня — правка кода. Если понадобится переключать их без пересборки — это отдельная задача,
параметры логично назвать `STT_MODEL`, `STT_DEVICE`, `STT_COMPUTE_TYPE`.

Конфигурация читается **один раз при импорте модуля**: правка `.env` требует перезапуска приложения.
