# Регламент базы знаний `docs/kb`

Технология ведения папки `docs/kb/`. Читатели — агенты (Claude) и владелец.
Устроено по образцу базы `skl-ut` (проект Сокол-Авто), словарь тегов адаптирован под этот проект.

## 1. Назначение и границы

База знаний — компилированный слой знаний **о системе**: устройство и приёмы, которые нужны,
чтобы в следующий раз сделать работу быстрее и не переоткрывать одно и то же.

Хранит:

- **устройство** — как устроены модули, потоки, форматы файлов и данных;
- **решения** — принятые архитектурные решения и **почему** сделано именно так (особенно неочевидные:
  почему буфер обмена возвращается назад, почему дубль в Obsidian пишется до отправки в API);
- **приёмы** — рабочие техники (как прогнать разбор фразы без микрофона, как посмотреть, что съел VAD);
- **интеграции** — внешние API и их подводные камни (SingularityApp, Obsidian-хранилище);
- **диагностики** — как локализовать типовую проблему (медленное распознавание, не срабатывают хоткеи);
- **регламенты-инструкции** — воспроизводимые процедуры.

НЕ хранит:

- **оперативные задачи** — они живут в `docs/tasks/` и в базу знаний не переносятся; из завершённой
  задачи в базу выносится только обобщённое знание отдельной карточкой;
- пересказ пользовательской документации — `README.md`, `DEPLOY.md`, `USAGE.md` каноничны,
  на них ссылаются, их не дублируют;
- листинги кода целиком — карточка объясняет замысел и указывает `файл:строка`, код читается в репозитории;
- значения секретов (токен Singularity, пути к личным хранилищам) — только имена параметров.

## 2. Формат файла

Фронтматтер:

```yaml
---
title: Локальный STT-сервер                     # человекочитаемый заголовок (для basic-memory)
вопрос: как отдать распознавание другим программам на этой машине   # на какой вопрос отвечает файл
ключевые_слова: STT_PORT, /stt, HTTP, PyAV, ogg   # слова для поиска, которыми это называют
модуль: app.py                # app.py | singularity | obsidian | tools | инфраструктура | общее
теги: [устройство, сервер-stt]  # из управляемого словаря (раздел 3)
статус: действует             # действует | устарело | черновик
обновлено: 2026-08-13
источник: откуда знание (разбор кода / замер / правка владельца / внешний документ), с датой
заменяет: имя-устаревшей-карточки   # только при замене (раздел 4)
заменена: имя-новой-карточки        # только у устаревших
---
```

- Поле `permalink:` дописывает **basic-memory** при синхронизации — служебное, **не трогать и не удалять**.
  Заодно он нормализует сам фронтматтер: переносит длинные строки и разворачивает `теги: [a, b]`
  в YAML-список. Это нормально, обратно не выправлять.
- Тело: суть без предисловий. Файл маленький и самодостаточный — агент читает его целиком.
- У карточек-**решений** обязательны строки **Почему:** и **Как применять:**.
- Ссылки на код — в виде `app.py:405`, `singularity/parser.py:222`. Строки протухают: при правке карточки
  сверяй номера, а при расхождении верь коду, а не карточке.
- Связи с другими единицами — wiki-ссылками: `[[карта]]`, `[[Локальный_STT_сервер]]`. Ссылка на
  несуществующий пока файл допустима — это заявка на будущую единицу.
- Именование файлов: кириллица, слова через подчёркивание, без дат в имени.

## 3. Словарь тегов (управляемый)

Теги — несущая ось базы (папок пока нет, раздел 7). Словарь закрытый: новый тег добавляется
**только по согласованию с владельцем** и вносится сюда.

**Тип знания** (ровно один на карточку):

`устройство` · `решение` · `приём` · `интеграция` · `диагностика` · `регламент`

**Тема / подсистема** (один и более):

`stt` · `аудио` · `гпу` · `хоткеи` · `оверлей` · `трей` · `логирование` · `конфигурация` ·
`очереди` · `singularity` · `obsidian` · `грамматика` · `сервер-stt` · `окружение` · `git` · `документация`

Правила: теги в нижнем регистре, слова через дефис. Прежде чем ввести новый тег — проверь,
нет ли близкого в словаре (не плодить `гпу`/`gpu`/`cuda`).

## 4. Актуальность

Проект активно дорабатывается, модули будут подменяться целиком — поэтому слой актуальности
живёт в карточках, а не в голове:

- изменилась реальность → **новая** карточка со ссылкой `заменяет:`; старой ставится
  `статус: устарело` и `заменена:`. Устаревшие карточки **не удаляются** — сохраняется история
  решений (почему когда-то сделали именно так);
- мелкая правка внутри той же реальности (уточнение, новый факт, съехавший номер строки) —
  правится на месте, обновляется `обновлено:` и дописывается `источник:`;
- карточка, оказавшаяся неверной, не правится молча — фиксируется как замена;
- агент, встретивший противоречие двух источников, **сообщает владельцу**, а не выбирает молча.

## 5. Правила записи

- **Ничего не записывается без подтверждения владельца.** Агент показывает текст карточки,
  владелец подтверждает или правит.
- Каждая единица датирована (`обновлено:`) и указывает `источник:`.
- Новая карточка противоречит существующей → агент показывает конфликт («записано иначе — что верно?»),
  а не пишет вторую версию молча.
- После добавления или переименования единицы обновляется `карта.md`.
- **Инструменты записи basic-memory (`write_note`, `edit_note` и подобные) не используются** —
  запись только вручную в файлы по этому разделу.

## 6. Доступ агентов и basic-memory

- **Точка входа** — `карта.md`: что в базе есть и когда куда идти. Указатель на неё — раздел в `CLAUDE.md`.
- **Навигация важнее поиска:** агент входит через карту и идёт по wiki-ссылкам; поиск — запасной вход.
- **basic-memory (MCP)** — слой семантического поиска по смыслу поверх файлов. Проект называется
  `aqualocal`; инструмент — `search_notes(project="aqualocal", query=...)`, найденный узел читать
  **целиком файлом**. При синхронизации инструмент сам дописывает `permalink:` — это нормально.
- Единый индекс basic-memory охватывает несколько проектов федерации (реестр — карточка
  `реестр_проектов` в проекте `main`). Файлы остаются источником правды, в git.
- **Эмбеддинги новых карточек** работающий сервер строит сам. Если семантический поиск новую карточку
  не находит (бывает после сбоев: нет места на диске, файл заблокирован, недоступен OpenRouter) —
  прогнать инкрементальную переиндексацию:
  `<python из окружения basic-memory> -c "from basic_memory.cli.main import app; app()" reindex -p aqualocal`
  (env-переменные OpenRouter взять из блока `basic-memory` в `~/.claude.json`, значения ключей в вывод не печатать).

## 7. Гигиена и структура

- Пока карточек мало — держим **плоско** (все файлы в `docs/kb/`), разделение только тегами.
  Разбивку на подпапки вводим, когда накопится (ось — по темам из словаря).
- Ревизия по мере необходимости: пройти карту, пометить умершие карточки, слить дубли.
- В `docs/kb/` не попадают: генерируемые файлы, черновики размышлений, оперативные задачи.
- База знаний **трекается в git** вместе с кодом: репозиторий публичный (форк), поэтому личных
  данных и секретов в карточках быть не должно — см. раздел 1.
